## Live system-audio transcription: verified, with a correction

The earlier live check was blocked by the audio-permission refresh. After the
owner's macOS interaction, Said relaunched and began receiving buffers, exposing
a distinct format error: two input buffers were being interpreted as one stereo
stream. The connected Display Audio device reports one hardware input channel;
including that playback device as an aggregate subdevice adds its input stream
beside the process tap.

The aggregate now contains only the private system-audio tap. It does not add
hardware input devices. Before copying, `CoreAudioTapBuffer` validates buffer
count, channels, frame alignment, and data sizes against the tap format. It
rejects unexpected layouts without reading sample memory. Regression tests
cover interleaved and planar stereo ownership, extra hardware inputs, incorrect
channel counts, and partial frames.

Playing `Dependencies/transcribe.cpp/samples/jfk.wav` through normal Mac system
playback produced actual captions in the running app after this fix. The visible
caption included “ask not what your country can do for you” and the following
sentence. This is the repository's documented public-domain JFK fixture. No
user conversation was recorded or exported. This proves live capture and
transcription on this Mac and its current Display Audio route, not other hardware
or a full output-device-switching matrix.

Apple references used during the repair:
- [Core Audio tap capture](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)
- [NSMenu screen-coordinate placement](https://developer.apple.com/documentation/appkit/nsmenu/popup(positioning:at:in:))
